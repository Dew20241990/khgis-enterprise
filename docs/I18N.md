# Internationalisation (Arabic / French / English)

The UI is fully localisable into **Arabic (RTL), French and English (LTR)**. There is exactly one mechanism:
a typed translation function `t(key, params?)` obtained from the app store. This page is the contract for
anyone adding or changing user-visible text.

```tsx
const { t, locale } = useApp();          // '@/store/appStore'
<h1>{t('workOrders.title')}</h1>
<p>{t('workOrders.countOf', { n: rows.length, total })}</p>
```

* The active language is `locale` (`'ar' | 'fr' | 'en'`). It is persisted in the browser and drives `<html lang>` and
  `<html dir>` (`directionFor(locale)` in `src/lib/documentSettings.ts`).
* `t` accepts only keys that exist — an unknown key is a **compile error** (`TranslationKey`).
* `{placeholder}` values are filled from the params object. Every language must use the same placeholders.

## Where strings live

| Place | What |
|---|---|
| `src/i18n/translations.ts` | The **core** dictionary: shell, navigation, login, common words (`save`, `status`, `open`, …). |
| `src/i18n/modules/<area>.ts` | One **feature module** per area (`dashboard`, `admin`, `territory`, `operations`, `epwg`, `shared`). Built with `defineModule({ ar, fr, en })`, which fails to compile if the three languages do not have exactly the same keys. |
| `src/i18n/modules/index.ts` | Registers the modules. |
| `src/i18n/domain.ts` | `domainLabel()` plus the shared `STATUS_KEYS` / `PRIORITY_KEYS` tables. |
| `src/lib/format.ts` | Locale-aware numbers, dates, times, month and weekday names. |

Key rules:

1. **Keys are globally unique** (tests fail on duplicates) and module keys are prefixed with the area/page, e.g.
   `inspections.filter.status`, `containers.form.capacity`. Use camelCase after the prefix.
2. **Reuse before you add.** Run `npm run i18n:find -- "<text in any language>"` (add `--exact` for whole-value
   matches). Common words (`status`, `type`, `date`, `name`, `save`, `cancel`, `open`, `critical`, …) and the
   units/currency/status words in `shared.*` already exist.
3. **No Arabic in French or English values, no empty values**, and identical `{placeholders}` in all three
   languages — all enforced by `src/i18n/coverage.test.ts`.
4. Write real translations, not transliterations. Use the platform's established terminology
   (French: *commune*, *wilaya*, *centre d'enfouissement technique (CET)*; English: *municipality*, *province*).

## Domain values vs. labels

Stored records keep **stable codes** (`'inProgress'`, `'near-capacity'`, `'critical'`) — never a translated label.
Labels are produced when rendering:

```tsx
import { domainLabel, STATUS_KEYS } from '@/i18n/domain';
domainLabel(t, STATUS_KEYS, row.status)     // translated; unknown values are shown as-is
```

* A feature that has its own value set defines a typed table (`DomainTable`: stored value → `TranslationKey`) next to
  its module, e.g. `src/i18n/modules/operations.domain.ts`. Tables may list legacy source spellings (including
  Arabic) as *keys*; those files live under `src/i18n/` and are exempt from the hard-coded-text scan.
* Select/filter `options` use the stored code as `value` and a translated string as `label`.
* Never compare against a translated label and never persist one.

## Entity names, user content, identifiers

Not translated: identifiers and codes (`M-01`, plates, file names), official proper names, text typed by users, and
free-text content of demo records. Entities that carry several names (`name`, `nameAr`, `nameFr`) are rendered with
the field matching the active language, falling back to another one when it is empty.

## Numbers, dates, units

Use `formatNumber(locale, n)`, `formatDate(locale, d)`, `formatTime`, `monthLabel(locale, i)`, `weekdayLabel(locale, i)`
from `src/lib/format.ts` instead of `toLocaleString('ar-DZ')` or hand-written month arrays. Arabic uses Latin digits
(matching the rest of the interface). Units and the currency come from `shared.unit.*` / `shared.currency.da`.

## Direction (RTL / LTR)

Use **logical** Tailwind utilities so layouts mirror automatically: `ms-*`/`me-*`, `ps-*`/`pe-*`, `text-start`/`text-end`,
`start-*`/`end-*`, `border-s`/`border-e`, `rounded-s`/`rounded-e`. Directional icons (chevrons, arrows) get
`rtl:rotate-180` (or `rtl:-scale-x-100`). Map overlay controls positioned over Leaflet may stay physical.

## Module-level labels

Hooks only work inside components. A module-level array that contains labels must hold **keys**, translated at render:

```tsx
const COLUMNS: { key: string; labelKey: TranslationKey }[] = [{ key: 'status', labelKey: 'status' }, …];
…  COLUMNS.map((c) => t(c.labelKey))
```

or be built inside the component with `useMemo(() => […], [t])`. Helper functions that need text receive `t`
as an argument.

## Language switching must not lose work

Language switching only re-renders; it must never remount a form or reset state (no `key={locale}`). Form field
definitions are rebuilt with new labels while `SmartForm` keeps its values (covered by `SmartForm.i18n.test.tsx`).

## Guard rails (tests and scripts)

| Command | Purpose |
|---|---|
| `npm run i18n:audit` | Lists remaining hard-coded UI text per file, in three categories: Arabic literals, `locale === …` ternaries that pick text, and Latin UI text. |
| `npm run i18n:audit -- --write-baseline` | Rewrites `src/i18n/hardcoded-text.baseline.json` after converting files (the baseline can only shrink). |
| `npm run i18n:find -- "text"` | Finds an existing key by text. |
| `npm test` | Key parity, duplicates, empty values, Arabic-in-FR/EN, placeholder parity, language switching, and the **ratchet**: no file may contain more hard-coded lines (in any of the three categories) than its baseline entry, and new files may contain none. |

Current baseline (2026-11-04): **1,004 Arabic lines in 43 files, 356 ternary lines in 21 files, 81 Latin lines in 25 files**.
`src/pages/AiAssistantPage.tsx` and `src/pages/SettingsPage.tsx` are at zero in all three categories.

A line that legitimately must contain Arabic (for example a language's own name in the language picker) carries
`// i18n-ignore: <reason>`.
